## 방법

1. ALIO RAG REST(`/api/search?...&corpus=bylaws&all_versions=1`)에서 같은 `edition_group`에 `superseded`와 다음 판이 함께 있는 규정을 찾고, 두 판본을 `loadDoc`으로 불러와 본칙을 조문 단위로 비교했습니다. 변경이 1～3개 조문이고 내용이 분명한 7건을 골랐습니다(7개 기관, 주제: 휴가 일수·수당 금액·절차·조문 신설·조문 삭제·용어 변경). 원천 파싱 오류가 있는 사례(C6, C7)는 원문을 사람이 대조해 실제 변경을 확정했습니다.
2. 사례마다 담당자가 쓸 법한 개정 의도 문장을 직접 썼습니다. 신판 문구를 그대로 옮기지 않았습니다(`replay-history.mjs`의 `CASES`).
3. `node app/scripts/replay-history.mjs run <모델> [사례]` — 구판 doc_id와 의도만 넣고 `auto:true`로 개정 흐름(`app/flows/amend.mjs`)을 그대로 실행합니다. 대상 조문(refs)은 지정하지 않습니다. 기관 프로필은 `public-institution`과 기관명만 넣었습니다.
   - **시간 차단**: 검색 결과에서 같은 기관·같은 제명의 다른 판본을 뺐습니다. 차단하지 않은 첫 C3 실행에서 같은 규정의 다른 판본(신판으로 추정)이 '유사 규정' 근거로 들어와 정답이 새어 들어갔기 때문입니다. 다른 기관의 이후 판본까지는 막지 못합니다.
   - 모델: `openrouter:openai/gpt-oss-120b`(7건 전부), `exaone`(대표 2건: C1, C4). C4·C5는 GPT-OSS로 한 번 더 돌렸고(`try2`), C5는 정답 조문을 지정한 진단 실행(`refs`)도 했습니다.
4. 자동 점수(`score()`): 실제 변경 조문 대비 재현율·정밀도, 핵심 값(must) 포함률, 항 단위 과잉·누락 변경, 개정 표기 삭제 수. 사람 판정(`review.json`, 0～2점): 대상·내용·대비표·개정문·부칙·근거.
5. `node app/scripts/replay-history.mjs summarize` → `cases.json`. 실행 원자료는 `runs/*.json`, 문서 세트는 `runs/*.md`에 있습니다.

LLM 호출은 모두 29회입니다. 기록된 27회에 시간 차단 전 C3 실행 2회(결과 파일은 덮어씀)를 더했습니다. 키 값은 기록하지 않았습니다.

## 실패·약점의 원인 (코드 위치)

1. **항·호 신설을 표현할 수 없음 → 흐름 전체가 중단**(C4×2, C5×2). 출력 스키마에서 insert는 조 단위뿐인데(`prompts.mjs:12,16`), 모델이 `after: "4" | "제6조③" | "⑤"`를 냅니다. `amend.mjs:112` 검증이 실패하면 재질의 메시지("규정에 없습니다")만 보내고 1회 뒤 중단합니다. 바뀐 조문이 하나라도 잘못되면 나머지 정상 변경까지 버립니다.
2. **부분 개정 문형이 사실상 꺼져 있음**. `amend.mjs:146`은 새 본문만 `\n{2,}`→`\n`로 줄이고 원문(`a.body`)은 그대로 둡니다. 그래서 `table.mjs:86`의 `op[i] === np[i]` 엄격 비교가 실패하고, 바뀌지 않은 항에서 `removed.length===0` → `null`이 되어 전문 대체로 떨어집니다.
3. **개정 표기·원천 이스케이프 때문에 대비표가 오염됨**. 모델이 `[개정 …]`·`<신설 …>`·`[본조신설 …]`을 지우거나 날짜를 지어내고(C1 `[신설 2024. 12. 27.]`), 원천의 `` \` ``·`#####`·큰따옴표 차이까지 diff에 잡힙니다(`table.mjs:46` `buildComparison`, `alio-rest.mjs` `normalizeSections`). 그 결과 바뀌지 않은 항이 "현행과 같음"으로 나오지 않습니다(C1-EXAONE, C2 ③, C5 9행).
4. **조문 탐색 핵심어 결함**. `text.mjs:2`의 JOSA가 명사 끝의 한 글자를 잘라 냅니다(휴가→"휴", 직무태만→"직무태", "장기재직휴"). `keywords(max=8)`(`text.mjs:4`)는 의도의 앞 절만 남겨, 여러 절로 된 의도의 뒤쪽 대상이 후보 12개 밖으로 밀립니다(C5 제15조 14위). 근거 검색도 같은 함수에서 4개만 씁니다(`common.mjs:38`).
5. **AI 추천 과다 + 자동 승인**. `pickArticlesPrompt`(`prompts.mjs:4`)가 최대 5개를 허용하고, `amend.mjs:81,85`는 그대로 수정 대상으로 넘깁니다. 그 결과 불필요한 조문이 수정안 입력이 되어 중복·과잉 변경이 생깁니다(C6 제66조, C5 제22·29조, C2 제12조).
6. **부칙 생성에 기준 정보가 없음**. `amendPrompt`에 오늘 날짜·구판 시행일·근거 법령의 시행일·기관 유형별 시행 문구(발령/이사회 의결)가 들어가지 않습니다. `addendaDoc`(`docset.mjs:24`)은 주어 누락·과거 날짜·"공포" 용어·"이 개정 규정은"(띄어쓰기 변형)을 보정하지 않습니다.
7. **가지조문 번호 '의1'**. `refs.mjs:74`의 `Math.max(0, …)+1` 때문에 가지가 없는 조 뒤에 신설하면 '제36조의1'이 됩니다(올바른 번호는 의2).
8. **조사·순서**. `table.mjs:107-108`이 "를"을 고정으로 붙여 '제35조의3를'이 됩니다(`josa()` 미사용). 대비표 행이 조 번호 순으로 정렬되지 않습니다(`amend.mjs:179` → `buildComparison`).
9. **삭제 항 번호 보존 미검증**. 모델이 "④ 삭제" 자리를 새 내용으로 덮어도 경고가 없습니다(`amend.mjs:153`의 paraLoss는 항 수만 셉니다).
10. **자기 규정의 다른 판본이 '유사 규정'으로 들어옴**. `common.mjs:42`는 같은 doc_id만 제외합니다. 실제 사용에서도 같은 규정의 구판·시행예정판이 근거로 섞일 수 있습니다.

## 수정 제안 (효과 큰 순서)

1. <b>(1번 원인)</b> 프롬프트에 "항·호·목의 추가·삭제는 op=amend로 해당 조문 본문 전체를 쓴다. insert는 새 조(제N조의M)만"을 명시합니다. 검증 실패 메시지도 고치는 방법을 알려 주도록 바꿉니다. `after`가 `제N조` 뒤에 항·호 표기가 붙은 꼴이면 amend 재요청으로 유도하고, 잘못된 변경만 빼고 나머지는 경고와 함께 살립니다. 이것만 고쳐도 GPT-OSS 실패 4회가 해소될 가능성이 높습니다.
2. <b>(2·3번 원인)</b> 결정적 정규화 단계를 둡니다. 원문과 수정안 모두 빈 줄을 줄이고, 조·항 끝의 개정 표기를 떼어 따로 보관한 뒤 비교가 끝나면 다시 붙입니다. 원천 `` \` ``·`#####` 제거와 따옴표 통일도 이 단계에서 합니다. `phraseDirective`는 공백 정규화 비교를 하고 변경이 없는 항은 건너뜁니다. 이렇게 하면 부분 개정 문형과 "현행과 같음"이 살아납니다.
3. <b>(6번 원인)</b> 부칙: 프롬프트에 기준일·구판 시행일·근거 법령 시행일·기관 기본 시행 문구를 넣고, 상위법 시행일이 다르면 단서를 쓰라고 지시합니다. `addendaDoc`에서는 주어를 보충하고, 기준일보다 앞선 시행일은 "발령한 날"로 바꾸고 경고합니다. 공공기관이면 "공포"를 "발령"으로 바꾸고, 근거 없는 경과조치는 확인 항목으로 돌립니다.
4. <b>(4·5번 원인)</b> 의도를 절 단위로 나눠 절마다 핵심어 점수를 매기고 후보를 합칩니다. JOSA에서 '가·만·도·의·이' 같은 한 글자 조사는 사전 단어와 충돌할 때 자르지 않습니다. AI 추천은 근거 구절 인용을 요구하고, `auto`일 때는 1순위 점수 대비 일정 비율 이상인 조문만 넘깁니다.
5. <b>(7·8·9번 원인)</b> `refs.mjs:74`를 `Math.max(1, …)`로 고칩니다. 개정문에 `josa(ref,'을','를')`를 씁니다. 대비표를 `artNum`으로 정렬합니다. 삭제 항(`삭제`)의 번호가 바뀌거나 내용이 덮이면 경고합니다.
6. <b>(10번 원인)</b> 근거에서 같은 기관·같은 제명의 다른 판본을 빼거나 '같은 규정의 다른 판본'으로 따로 표시합니다.

남은 약점: 요구가 여러 갈래인 의도(C5)는 대상 조문 추천이 실행마다 달라집니다. 화면에서는 추천 조문을 사람이 확인·수정하는 단계(게이트)가 있어 재현 실험(자동 승인)보다 유리합니다. 새 조문으로 둘지 기존 조문에 넣을지(C4)는 설계 선택이라 실제와 다를 수 있습니다.

## 한계

- 표본이 7건(GPT-OSS 첫 실행 7회, EXAONE 2회, 보강 후 21회)이라 수치는 경향일 뿐 성능 추정이 아닙니다. 모델 응답은 실행마다 달라집니다(C5 1차 실패, 2차 완료).
- 실제 신판이 정답이라는 보장은 없습니다. 기관이 실제로 택한 구조(조 신설 vs 호 추가)와 다른 합리적 설계도 엄격 점수에서는 감점됩니다(EXAONE C4).
- 의도 문장은 검증자가 실제 변경을 알고 쓴 것입니다. 실제 담당자보다 구체적일 수 있어 대상 탐색이 실제보다 쉬웠을 수 있습니다.
- ALIO 원천 파싱 오류(C6 신판 제65조가 제64조에 붙음, C7 부칙이 본칙 제2조로 파싱, C7 중간 판본 부재)는 사람이 원문으로 보정했습니다. 항 단위 자동 점수(`para_*`)는 C6에서 정확하지 않습니다.
- 시간 차단은 같은 규정의 다른 판본만 막습니다. 다른 기관의 이후 판본이나 현행 법령은 개정 시점 이후의 정보일 수 있습니다.
- 사람 판정은 검증자 1인이 매겼습니다.
