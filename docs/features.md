## 1. 한 줄 소개와 문제

**규정을 새로 만들고(제정) 고치는(개정) 일을 돕는 에이전트.** 공공기관·중앙행정기관·지방자치단체의 규정 담당자가 문장 하나로 요청하면, 에이전트가 유사 규정과 상위 법령을 조사하고 조문 초안·신구조문대비표·제·개정 이유서·부칙·예고문·인용 정정 목록·절차 서식까지 만든 뒤, 절차의 다음 할 일을 안내합니다.

**해결하려는 문제**

| 담당자의 어려움 | 규정 새로고침의 해결 |
|---|---|
| 무엇부터 해야 하는지, 어떤 문서가 필요한지 막막함 | 기관 유형별 절차 템플릿 + "다음 할 일" 패널 + 단계별 서식 자동 작성 |
| 유사 지침을 찾아 참고하고, 상위법 위임 범위와 조문 체계를 확인해 수기 작성 | ALIO 공시 내규(약 340개 공공기관)·법령·표준권장안 조사, 조문 체계 설계, 위임 조항 대조 |
| 신구조문대비표·부칙을 수작업으로 작성 | 대비표(밑줄·현행과 같음·신설·삭제 관행)·개정문·부칙을 코드가 결정적으로 생성 |
| 조 번호 이동에 따른 인용 정정 대상을 육안으로 확인 → 누락 우려 | 조 번호 재배열을 계산해 같은 규정·같은 기관 다른 규정의 인용 정정 목록을 자동 산출 |

## 3. 시스템 구성

```
브라우저(React + shadcn/ui, 빌드본)  ──/api──▶  Node.js 서버(외부 패키지 없음)
                                              ├ 작업 실행기: 단계·사람 확인(게이트)·실행 기록
                                              ├ 업무 흐름: 개정·제정·대화형 에이전트·상위법 영향·유사 비교·점검·법령 확장(+보강 기능)
                                              ├ 결정적 엔진: 조문 파서(hwpx/txt/md)·인용 추출·조번호 재배열·대비표·개정문
                                              ├ 데이터 어댑터: ALIO RAG REST(기본) · ALIO RAG MCP(인용관계) · 법제처 Open API · 업로드
                                              └ LLM 어댑터: OpenAI 호환 1개 인터페이스(EXAONE·GPT-OSS·Gemma·Nemotron·사용자 지정)
```

- **결정적 처리와 AI 초안 분리**: 원문 조회, 대비표, 개정문 형식, 조 번호 이동·인용 정정, 규칙 점검은 코드가 처리합니다. 모델은 조문 문안·이유서·요약·판단 보조만 하며, 응답은 JSON 형식·조문 실재·근거 ID를 서버가 검증한 뒤에만 씁니다.
- **사람 확인 게이트**: 대상 조문·참고 근거·조문 체계·대상 규정 선택에서 멈추고 담당자가 고릅니다.
- **근거 표기**: 모든 산출물에 근거 목록(문서 ID·조문·판본·시행일)과 "AI 초안" 고지를 붙입니다. 판본 경고(구판·시행예정·폐지·근사 판정)를 표시합니다.

## 4. 기능 상세

각 기능: 목적 · 입력 · 처리 단계 · 산출물 · 근거·검증 · 한계 · 시연 예.

### 4.1 개정 ✅
- **목적**: 개정 의도를 말하면 조문 수정안과 신구조문대비표를 포함한 개정 문서 세트를 만든다.
- **입력**: 대상 규정(ALIO 검색 / hwpx·txt·md 업로드·붙여넣기 / 법령), 개정 의도(문장), 선택: 조문 직접 지정, 조 번호 처리 방식(가지조문 유지·번호 재배열).
- **처리**: ① 원문 불러오기(판본 경고, ALIO 원천 데이터의 본칙·부칙 오표기 자동 보정) ② 대상 조문 찾기(핵심어 점수 + AI 추천 → **사람 확인**) ③ 근거 조사(유사 기관 규정·ALIO 법령·법제처 현행 법령 조문 → **사람 확인**) ④ 수정안 작성(LLM, 조문 실재·근거 ID 검증, 실패 시 재시도 후 중단) ⑤ 인용 정정·영향(조번호 재배열 계산, 같은 기관 다른 규정까지 인용 정정, 변경 조문을 인용하는 조문·별표·서식 표시) ⑥ 문서 세트.
- <b>산출물(13종)</b>: 개정문(「제79조제1항 중 "10일의"를 "20일의"로 한다」 형식), 신구조문대비표(변경 어절 밑줄·"현행과 같음"·<신 설>·<삭 제>), 개정 이유서, 부칙, 예고문(기관 유형별 사전예고·행정예고·입법예고), 인용 정정·영향 목록, 검토 체크리스트, 협조 요청 공문, 근로자 의견 청취서·동의서(근로조건 관련 시), 법무 검토 의뢰서, 심의 안건, 이사회 부의안(공공기관), 공포·발령문 + 근거 목록. Markdown·HTML(인쇄/PDF)·대비표 CSV로 내보내기(화면에서 고친 내용 그대로).
- **검증**: 수정안이 원문보다 크게 짧거나 항 수가 줄면 경고, 근거 없는 변경 표시, 근로조건이면 근로기준법 제94조 절차 표시.
- **한계**: 적법성 판정 아님. 같은 기관 다른 규정은 제명 인용으로 찾은 최대 5개까지.
- **실측**: 대구경북첨단의료산업진흥재단 취업규칙 제79조(배우자 출산휴가 10일→20일, 90일→120일) — EXAONE 72초, GPT-OSS 6초, Gemma 9초, Nemotron 30초 모두 통과. 조문 신설+번호 재배열: 조 이동 48건·인용 정정 10건, 외부 법령 인용은 정정하지 않음, 문서 14종(16초, GPT-OSS).
- **산출물 추가**: 단체협약 정합성(같은 기관), 불이익 변경 후보, 상위 기준·지적사항 근거.

### 4.2 제정 ✅ (보강 🛠)
- **입력**: 종류(기관 유형별: 규정·지침·훈령·조례 등), 제명, 제정 목적, 상위법 위임 조항(법령 탭에서 조문 추가 또는 붙여넣기, 비우면 후보 제시), 함께 정비할 기존 규정(선택).
- **처리**: ① 위임 조항 확인(+같은 법 정의 조문) ② 유사 규정 조사(ALIO 기관 다양성, 부처는 법제처 행정규칙, 지자체는 자치법규) + 유사 규정 목차 수집 ③ 조문 체계 설계(장·조, 8～14개 조, 근거 ID → **사람 확인**에서 조문 빼기) ④ 장별 병렬 조문 초안 + 이유·부칙 별도 작성 ⑤ 검증(조 번호 연속, 내부 인용 실재, 제재·의무 조항의 위임 근거) ⑥ 문서 세트(제정안 전문, 대비표 <신 설>, 부칙의 다른 규정 정비 대비표, 이유서, 예고문, 체크리스트, 절차 서식).
- **실측**: 「가나다공단 직장 내 괴롭힘 예방 및 처리 지침」(근로기준법 제76조의3 근거) 4개 장·12개 조 — EXAONE 267초, GPT-OSS 16.5초, Gemma 25초, Nemotron 46초.
- **보강 ✅**: A1 위임 범위 검토표, A2 상위 기준 근거, C3 단체협약 정합성, B1 의견 반영(4.9 참고).

### 4.3 대화형 에이전트 ✅
- **입력**: 자연어 요청(예: "대구경북첨단의료산업진흥재단 취업규칙의 배우자 출산휴가를 남녀고용평등법 개정에 맞게 20일로 고쳐야 해"), 선택: 대상 규정 미리 지정.
- **처리**: 모델이 허용 도구 목록(규정 검색·원문 불러오기·조문 보기·법령 검색·인용 탐지·판본 비교·유사 규정·개정안·제정안·상위법 영향·비교표·점검·절차 안내·사용자 질문·종료) 중에서 <b>계획(JSON)</b>을 세움 → 코드가 도구 실행·기록 → 도구 실패 시 다음 행동 재질문(최대 3회) → 사람 확인 지점에서 멈춤 → 문서 세트·다음 할 일 제안. 같은 호출 반복 차단, 12단계 상한, 계획 실패 시 기본 흐름 전환, 모델 없으면 규칙 분류.
- **모델 비종속**: 모델 고유 function calling 미사용. 4개 모델 실측 통과(EXAONE 212초, GPT-OSS 20초, Gemma 19.5초, Nemotron 49초).

### 4.4 절차 안내와 단계별 서식 ✅
- 기관 유형 3종 템플릿(공공기관 내부규정 / 중앙행정기관 훈령·예규·고시 / 지자체 조례·규칙): 단계별 할 일, 필요 문서, 근거(근로기준법 제94조, 공공기관운영법 제11조·제17조, 행정절차법 제41·43·46조, 훈령·예규 등의 발령 및 관리에 관한 규정, 지방자치법 등 — "기관 규정 확인 필요" 명시).
- 진행률 링, 다음 할 일, 결과 문서 세트와 연동된 준비 문서 ✓ 표시. 템플릿 JSON은 기관이 편집 가능.
- 서식 7종: 협조 요청 공문, 근로자 의견 청취서·동의서, 법무 검토 의뢰서, 심의 안건, 이사회 부의안, 의회 제출 조례안, 공포·발령문.

### 4.5 상위법 영향 ✅
- **입력**: 법령명·조문 → 「판본 불러오기」(ALIO 법령 판본 연혁에서 현행·직전 변경본 자동, 다른 판본 선택 가능) 또는 개정 전·후 조문 직접 입력. 주제·기관 범위(선택).
- **처리**: 수치 변경(10일→20일) 추출 + AI 요약 → 법령명 인용·주제어(줄인 변형 포함) 검색 + MCP 인용관계 → **주제 문장과 조문 제목 기준**으로 개정 전 값 잔존(개정 후보)·개정 후 값(반영됨)·확인 필요 판정 → 개정 탭으로 바로 연결.
- **실측**: 남녀고용평등법 제18조의2 → 80개 후보 조문 중 개정 후보 2(대구경북첨단의료산업진흥재단 취업규칙 제79조, 한국고전번역원 제29조), 반영됨 30, 확인 필요 48. 판본 21개 조회.
- **한계**: 검색 기반 근사(전수 아님), 위반 판정 아님.

### 4.6 기관 비교(F7) ✅ (+분포)
- **A 우리 기관 ↔ B 비교 대상**: 우리 기관을 이름 자동완성으로 고르면 기관 유형·주무부처가 채워지고, 비교 대상을 ① 같은 주무부처 ② 같은 기관 유형(공기업 시장형·준시장형, 준정부 기금관리형·위탁집행형, 기타공공기관) ③ 직접 고른 기관(최대 10곳) ④ 전체에서 고릅니다. 기관 목록은 ALIO 공시 355개 기관(`app/institutions.json`).
- **주제에 맞는 항만 비교**: 주제어 중 대상 낱말("배우자 출산휴가")이 실제로 들어 있는 항을 골라 발췌합니다. '일수·기한' 같은 속성 낱말은 빼고, 복합어는 나눠 맞춥니다(「배우자의 출산을 이유로 휴가」도 일치). 검색 1순위가 주제와 다른 조문이거나 부칙 적용례이면 그 기관 규정을 다시 찾고, 그래도 없으면 **표에서 빼고 "주제 조문을 찾지 못한 기관"으로 따로 알립니다**(규정이 없다는 뜻이 아님을 표기).
- 핵심 값은 원문 구절 그대로 옮기고 원문에 없는 값은 버립니다. 모델이 없으면 주제 문장의 첫 수치를 규칙으로 뽑습니다. 우리 기관 행을 맨 위에 두고 값이 다른 기관에 「우리와 다름」을 붙입니다. 한 조문에 경우별 값이 여럿이라 상대 값이 우리 조문에도 있으면(업무상 180일·그 밖 60일) 「경우별 값 · 원문 확인」으로 표시합니다.

- 실측(2026-11-11, GPT-OSS): 소상공인시장진흥공단 · 같은 주무부처(중소벤처기업부) · "배우자 출산휴가" → 6개 기관, 20일 3곳·10일 1곳, 우리 기관은 별표(경조사휴가 표)에서 찾음. 같은 기관 유형(준정부기관 기금관리형) · "병가 일수" → 6개 기관 모두 병가 조문, 60일 4곳.

### 4.15 초안 품질: 자체 검토 단계 (2026-11-11)

개정·제정 초안을 만든 뒤 **자체 검토** 단계를 거칩니다.
1. 코드가 먼저 찾습니다: 규정에 없던 법률 주체어(사업주·근로자 — 정의 조항·「근로자의 날」은 제외), 법령 검색으로 확인되지 않는 법령명, 공공기관 규정의 공무원 법령 인용.

4. 문장으로 쓴 항 삭제(「③ … 규정은 삭제한다」)는 법령 관행 「③ 삭제」로 바꿉니다.

| | 보강 전 | 보강 후 |
|---|---|---|
| Q1 업로드 복무규정 → 남녀고용평등법 맞춤(20일·전부 유급·120일·3회·90일 삭제·규정 용어) 6개 항목 | 평균 0.89, 만점 2/5회 | **만점 4/4회** |

| 실제 개정 이력 재현(7건 × 3회) 완료 / 재현율 / 정밀도 / 핵심 값 | 21/21 · 0.80 · 0.88 · 0.94 | 21/21 · 0.76 · **0.92** · 0.89 |

### 4.18 원문 보기 · 원문 검색(AI 없이) (2026-11-11)

- **원문 보기**: 담당자가 판단해야 하는 자료를 누르면 창이 열려 해당 조항과 문서 전체를 봅니다. 문서 전체 탭은 그 조문 위치로 이동해 강조합니다. 법제처 자료에는 국가법령정보센터 원문 링크가 붙습니다.
  - 대상: 사람 확인 단계의 선택지(대상 조문·근거·위임 조항·일괄 개정 지점·규정 후보), 단계별 근거·출처, 근거 자료 목록, 기관 비교 표, 법 개정 영향 후보·레이더, 법령 체계의 기관 규정, 규정 점검 결과
  - 자료: ALIO 내규·법령·단체협약·공시자료, 법제처 법령·행정규칙·자치법규, 올린 자료
- **원문 검색**: 머리글의 「검색」 단추 또는 Ctrl+K로 엽니다. 메뉴(F키)는 늘리지 않았습니다. 모델을 쓰지 않습니다.
  - 검색 방식: 키워드·의미·통합(하이브리드)
  - 자료 범위: 기관 내규·법령·단체협약·공시자료·전체. 중앙부처·지자체 사용자는 법제처 행정규칙·자치법규도 고를 수 있습니다.
  - 좁히기·정렬: 기관·주무부처, 본문까지, 기관별 1건, 결과 수(15～100), 관련도순·최신순
  - 결과: 검색어 강조 발췌, 더 보기, CSV 내려받기, 누르면 원문 보기
  - alio.k-union.kr 검색 화면의 옵션을 참고했습니다. 실측: "육아휴직 대체인력" 기관 내규 통합 검색 29건, 2.6초.
- 같은 유형 버그 점검(치명 3건과 같은 「이름을 잘라 비교·앞부분만 비교」): 법령 판본(「국가공무원법」에 「국가공무원 복무규정」 섞임), 법령명 존재 확인(「근로기준법 특례법」 통과), 영향 분석의 법령 인용 판단, 하위 법령 이름, 업로드 제명 첫 낱말을 고쳤습니다(재현 테스트 포함).

## 6. 모델 비종속 검증
같은 코드·같은 입력, 3개 시나리오 × 4개 모델 모두 통과(`docs/model-verification.md`). 화면 「모델 설정」에서 공급자·모델 교체, 본인 키 입력(브라우저 탭에만 보관), 사용자 지정(OpenAI 호환: 행안부 AI 공통기반 등).

## 7. 개발 원칙
- 개발 방향: 서버 외부 패키지 0, 모듈 분리, 테스트 249개(레드팀·실제 개정 이력 재현 테스트 포함).
- 모델 비종속: 4개 모델 실측.
- 자료: 공개 데이터만 사용(시험용 규정은 `app/test/fixtures/`).
- 원본 보호: 업로드 원본 0444·해시 검증, 산출물 분리.
- 라이선스: 서버 무의존, 화면 빌드 구성요소는 MIT 등 허용 라이선스.

## 8. 보안
국내 IP(로그인 없이 공개), CSP, Origin 검사, IP별 요청 한도, 요청 크기·업로드 일일 총량, 동시 작업 제한, 신뢰 프록시에서만 X-Forwarded-For, 사용자 지정 모델 주소의 DNS 해석 후 사설망 차단, 서버 키 일일 사용 한도, 압축 폭탄·정규식 폭주 방어, 비밀값은 `.private/`만.
